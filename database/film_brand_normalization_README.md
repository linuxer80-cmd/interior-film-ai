# 필름 브랜드 입력 통일

운영 Supabase 프로젝트 `gxtvvzysuhexhpljpswj`의 SQL Editor에서 `database/film_brand_normalization.sql`을 한 번 실행합니다. 운영 DB 접근 권한이 현재 커넥터에 없어 자동 적용하지 않았습니다.

- 현대 / 현대&C / 현대L&C / 보닥 등 → 현대보닥
- 영림 / 영림필름 / 영림 인테리어필름 등 → 영림
- 다른 브랜드는 임의로 합치지 않습니다. 특히 예림과 영림은 다릅니다.

앱의 예정·실제 자재 저장, 자재 제품 등록, 단가표 인식, 제품 대조, 주문 브랜드 필터, 재고 브랜드 표시, 자재비 통계에서 같은 기준을 사용합니다. 카탈로그 검색에서 선택한 기존 제품 ID를 검증해 연결하고, 모호한 경우 자동으로 단가를 선택하지 않습니다. 업체별 가격 조회와 방염/비방염 구분은 유지합니다.

SQL은 카탈로그·현장자재·롤의 브랜드 이름만 정리하고, 이후 DB 쓰기 경로에도 정규화 트리거를 적용합니다. 제품/자재/롤 ID, 수량, 금액, 가격 및 연결 ID는 바꾸지 않습니다. 기존 업무 검증 트리거와 RLS를 비활성화하지 않습니다. 업무 잠금으로 SQL이 거부되면 전체 트랜잭션이 롤백되므로 오류를 확인한 후 진행해야 합니다.

같은 표준 브랜드·제품번호를 가진 카탈로그가 여러 개면 해당 카탈로그 이름을 강제로 합치거나 ID를 삭제하지 않고 마지막 결과표에 기존 ID를 표시합니다. 이는 확인 대상이며 자동 삭제 대상이 아닙니다. 앱은 해당 제품을 기존 ID로 선택할 수 있고, ID 없이 여러 후보가 있으면 자동 연결/단가 대입을 하지 않습니다.

검증: JS 입력·제품/단가 연결, 예정 자재 API, 통계, 잠정 자재비 및 PostgreSQL(PGlite)의 신규 저장·기존 이름 정리·중복 카탈로그 보존·재실행 검증. 운영 DB와 실기기 저장 검증은 SQL 적용 후 필요합니다. 기존 dealer-price-import 테스트 1건은 변경 전 모듈에서도 같은 실패가 재현되어 이번 변경에 포함하지 않았습니다(영림 기본 코드의 비방염 추론에 대한 기존 기대값 불일치).
