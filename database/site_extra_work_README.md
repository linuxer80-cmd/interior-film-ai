# 현장 변경 확인 · 추가 작업 승인

## 적용
1. 운영 Supabase 프로젝트 `gxtvvzysuhexhpljpswj`의 SQL Editor에서 `database/site_extra_work.sql` 전체를 실행합니다. 다른 프로젝트에 실행하지 않습니다.
2. 결과 `추가 작업 승인·중복 정산 방지 설정 완료`와 RLS=true / anon_select=false / authenticated_select=false를 확인합니다.
3. main 배포가 Ready가 되면 앱을 새로고침합니다.

## 사용
- 현장 변경 확인: 시공자·관리자 현장 상세 → 현장정보 → 현장 변경·확인 현황. 기존 site_operations 변경 이벤트·수신자·검토 버전을 재사용합니다. 시공자는 최신 내용을 조회한 후 확인하며 관리자는 확인/미확인 이름과 시간을 봅니다. 최근 100개 변경 기록 범위는 기존 API와 같습니다.
- 추가 작업: 시공자 현장 상세 → 추가 작업 → 내용·요청 금액(선택)·사진(최대 5장)을 등록합니다. 반려 요청을 고쳐 다시 제출할 때는 새 요청을 작성합니다.
- 관리자 홈의 승인 대기 카드 또는 현장 상세 → 추가 작업에서 금액 확정·승인 / 사유와 함께 반려합니다.
- 관리자 본인도 소속 업체 현장에서 요청과 검토를 할 수 있습니다. 다른 업체에 배정된 관리자는 해당 업체의 시공자 권한만 가집니다.
- 고객과 금액을 합의했는지는 관리자가 별도로 확인합니다. 시공자 지급액은 자동 변경하지 않습니다.

## 금액 처리
승인된 금액은 현재 sites.contract_amount에 한 번 추가합니다. 계약금액이 없으면 최신 승인 완료보고 금액을 기존 금액으로 사용합니다. 둘 다 없으면 먼저 기존 계약금액을 확정해야 합니다. 이미 계약금액에 포함한 추가 작업은 0원으로 승인합니다.

수익 API와 site_receivable_balances가 사용하는 계약금액을 직접 갱신하므로 수익·미수금에 반영됩니다. 입금 내역은 수정하지 않습니다. 저장·발행된 견적서는 자동 변경하지 않고 상담 견적 화면에 승인된 부속 내역을 표시합니다. 승인된 요청은 재승인·수정·취소할 수 없습니다. 이후 계약금액을 수동 변경하면 현재 계약금액을 기준으로 관리해야 합니다.

## 권한·사진
새 테이블은 RLS를 켜고 anon/authenticated의 직접 접근을 차단합니다. 서버에서 토큰을 검증하고 기존 현장 접근 해석기로 업체·배정을 확인합니다. 승인 RPC는 service_role만 실행할 수 있고 DB 내부에서 활성 업체 관리자 여부를 다시 확인합니다. 현장·요청 잠금과 상태 검사로 이중 승인을 차단합니다.

사진은 기존 work-photos 버킷의 extra-work/업체/현장/사용자 경로에 저장하며 조회 권한을 통과한 요청에만 5분짜리 서명 URL을 제공합니다. 파일은 브라우저에서 축소하고 서버에서 개수·합계 크기·파일 서명을 검증합니다. 기존 버킷 공개 여부를 바꾸지는 않습니다.

## 검증
- 순수 입력/사진 검증, 실제 접근 해석기를 사용한 API 권한·중복 제출 테스트.
- PostgreSQL(PGlite)에서 승인 중복, 권한 거부, 반려·취소, 금액 기준, 권한/RLS, 롤백 테스트.
- 변경 확인 UI에서 최신 버전 전달 및 관리자 확인/미확인 명단 테스트.
- 운영 DB 실행과 실기기 사진 업로드는 별도 확인이 필요합니다.
