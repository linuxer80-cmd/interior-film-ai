# 관리자 직접 시공 통합

관리자 홈의 **내 시공 · 업체 설정**에서 운영 방식을 선택한다. 기본값은 기존 동작을 유지하는 관리 전담이다.

- 대표 혼자: 예정·진행 현장을 대표 참여 대상으로 자동 표시한다. 출근한 현장은 완료 이후에도 참여 이력을 유지한다. 현장별 참여 해제도 가능하다.
- 대표와 직원: 현장 상세의 **내 시공·출근**에서 대표 참여를 선택한다. 직원 배정·책임팀장·검수 절차는 유지한다.
- 관리 전담: 직접 시공 목록을 숨긴다. 이미 출근한 현장은 퇴근 기록을 마칠 수 있다.

현장 상세에서 자재 반출·반납, 재단 최적화와 재단메모 사진 읽기, 경비 및 완료보고를 관리자 로그인으로 이용한다. 기존 현장·롤·보고서 API를 공유하고 시공자 계정이나 가짜 직원 레코드를 만들지 않는다.

## 적용 순서

1. 실제 앱 Supabase 프로젝트에서 `database/owner_work.sql`을 실행한다. 이 SQL은 재실행 가능하고 기존 업무 테이블을 변경하지 않는다.
2. 해당 테이블의 RLS 활성화와 `anon`/`authenticated` 접근 차단을 확인한다. 서버 service role만 접근하며 각 API는 인증된 활성 업체 관리자를 검증한다.
3. 브랜치를 배포하고 `/admin/owner-work`에서 운영 방식을 설정한다. 설정 전에는 관리 전담이다.
4. 실제 관리자 로그인으로 현장 참여 → 출근 → 자재 반출·반납 → 재단 → 완료사진·경비 → 완료보고 → 퇴근을 검증한다.

## 출퇴근·대표 인건비

현재 대표 기록은 **한국 날짜 기준 하루 한 현장**이다. 동일 버튼을 반복해도 출근 시간·퇴근 시간·대표 인건비가 중복 저장되지 않는다. 오늘 현장 시공일에만 새 출근을 허용한다. 관리자 본인의 수동 기록이며 GPS 검증 출퇴근으로 표시하지 않는다.

대표 인건비는 선택한 경우 출근 시점의 일당을 스냅샷으로 기록한다. 설정 변경은 새 기록부터 적용한다. 현장 수익 API에만 합산하며 직원 지급·출퇴근 급여·계좌 송금 목록은 건드리지 않는다. 다른 현장으로의 당일 비용 배분이나 반일 계산은 이번 변경에 포함하지 않는다.

## 원가 미입력

기존 롤 반출·반납 확인과 사진 검증은 유지한다. 추적 자재 원가 누락은 경고로 표시하고 완료보고 제출을 허용한다. 누락 원가는 임의로 저장하지 않는다. 실제 자재의 단가가 null이면 현장 수익과 합계에 확정 대기 안내를 표시한다. 방염 여부는 기존 창고 롤 정보를 사용하며, 이번 변경에서 제품 코드로 방염 여부를 새로 추정하지 않는다.

기존 재고 RPC가 롤별 실제 매입원가를 완전히 반영하는지의 운영 DB 검증은 별도 필요하다. 이 변경은 `plannedDealerPrice`의 대체 단가 추정이나 기존 재고 SQL을 수정하지 않는다.

## 검증

- `node --test tests/owner-work.test.mjs tests/worker-report-submit.test.mjs`: 10개 통과.
- PGlite PostgreSQL에서 SQL 2회 실행, RLS·권한, 날짜별 고유 키, 퇴근 시간 제약 검증 통과.
- 프로덕션 빌드 통과. 로컬 빌드에는 공개 Supabase URL/anon placeholder를 사용했으며 운영 DB 요청을 하지 않았다.
- 전체 테스트: 474개 중 422 통과, 19 skip, 33 실패. 수정 전 기준도 동일한 33개 실패이며 추가 실패 없음.

운영 DB에 새 SQL을 적용하거나 실사용 데이터를 변경하지 않았다. 실제 로그인 기반 end-to-end 검증은 SQL 적용 후 필요하다.
