# 시공 사진 분석·유사 사례 판별 기준

## 서로 다른 두 가지 판단

1. 대량 등록의 동일 대상 판별: **물리적으로 같은 장/문**이어야 한다. 날짜·장소·색상만으로 합치지 않는다. 문 개수·폭 비율·거울·옆 벽·대상의 끝 위치를 근거로 삼는다. 불확실하면 따로 두고 관리자가 묶는다.
2. 견적의 유사 사례 판별: 서로 다른 현장이더라도 **같은 시공 범위, 비슷한 구조와 규모**라면 참고 가능하다. 배경·색상·조명 차이 때문에 제외하지 않는다. 같은 색상만으로 비슷한 시공이라고 판단하지 않는다.

## 이번 변경

- 시공 대상 공통 규칙을 고객 분석, 대량 등록, 후보 사진 비교에서 공유한다.
- 냉장고 없는 냉장고장의 빈 칸·측판·상단 수납부와 옷 수납장을 구분한다.
- 주방 가구의 `도어`를 출입문으로 오인하는 정규화 오류를 수정한다.
- 원래 카테고리의 냉장고장 단서를 표준화 과정에서 잃지 않는다.
- 견적 사진이 잘리거나 식별이 불가능하면 확인이 필요하다. 보이는 문 수를 전체 문 수로 추측하지 않는다.
- 텍스트 임베딩은 검색 후보를 찾는 데만 쓴다. 검색은 최대 50행에서 시작하고, 같은 시공 범위의 독립 시공건으로 중복을 제거한다.
- 금액·시공 범위는 업체 소유 `work_items`에서 다시 읽는다. RPC의 가격·사진 경로를 신뢰해 사용하지 않는다.
- 등록된 업체 소유 사진만 조회해 상위 최대 4건을 실제 고객 사진과 비교한다. 고객 사진 최대 2장, 사례별 최대 2장, 비교 요청 1회다.
- 모델에는 가격과 텍스트 점수를 주지 않는다. 대상, 범위, 구조, 규모 네 항목이 모두 적합하고 구체적 근거가 있어야 금액 계산에 사용한다.
- 비교가 실패/불완전/불확실하면 금액을 계산하지 않는다. 텍스트 검색 점수로 대체하지 않는다.
- 고객에게 확률로 오인될 수 있는 유사도 %를 표시하지 않는다. 사진 비교 근거·차이점을 보여준다.
- 평균은 검증된 서로 다른 시공건 실제 금액의 평균이다. 범위는 관측된 최소~최대 금액이다. 1건이면 같은 참고금액만 표시한다. 기존 일률적인 ±10% 범위는 제거했다.
- `history` 사진은 전후 미확인 참고사진으로 표시한다. 임의로 시공 후 사진으로 바꾸지 않는다.

## 비용과 운영

- 사진 비교 단계가 추가되므로 실제 사용 시 AI 호출 비용과 대기 시간이 늘어난다. 모델 사용량과 비교 후보 수를 기존 검색 사용 로그에 기록한다.
- 추가 비교는 최대 4개 사례에 한정한다. 사용 한도 검사는 임베딩/사진 비교 전에 한다.
- 기본 모델은 기존 `gpt-5.6-luna`를 유지한다. 서버의 `OPENAI_VISUAL_COMPARE_MODEL`로 비교 모델만 지정할 수 있다. 모델 변경은 같은 평가 사진으로 검증해야 한다.
- 대량 등록도 구조를 식별하기 위해 `detail: high`를 사용한다. 정확도/추가 비용 효과는 실제 사진 평가가 필요하다.
- 새 테이블·컬럼·벡터 재생성은 필요 없다. 저장된 과거 데이터의 분류나 금액을 자동으로 바꾸지 않는다.
- 텍스트 검색 상위 후보에 적절한 사례가 없으면 시각 비교도 찾을 수 없다. 따라서 검색 단계의 후보 누락률도 별도로 측정해야 한다.
- 이미 잘못 묶이거나 잘못된 범위로 가격이 저장된 과거 자료를 완전히 복구하는 기능은 아니다. 비교 사진에서 혼합 범위가 보이면 제외하도록 했다.

## 확인한 것과 아직 확인하지 못한 것

코드 검증은 실제 API 경로, 요청 이미지 전달, 범위 필터, 사진 비교 결과 검증, 실제 금액 읽기, 회사 간 분리, 불확실한 결과 제외, 사용량 기록, 프런트 결과 유지 흐름을 모의 응답으로 검사한다. 실제 AI의 정확도 측정과 구분한다.

현재 받은 자료는 화면 캡처다. 원본 시공 사진으로 실제 모델 평가를 수행하지 않았다. 따라서 인식 정확도, 오묶음 비율, 검색 정답률, 실제 비용/지연을 검증했다는 주장을 하지 않는다.

원본 사진이 준비되면 다음 사례를 고정 평가셋으로 사용한다.

| 사례 | 기대 결과 |
| --- | --- |
| 27722.jpg, 27591.jpg | 냉장고장으로 분류. 붙박이장으로 확정하지 않음 |
| 27953.jpg, 28173.jpg, 27619.jpg | 앞 2장은 동일 대상. 3번째는 별도 대상 |
| 하부장만 보이는 사진 + 싱크대 전체 사례 | 전체 시공 금액 제외 |
| 같은 흰색, 다른 문 수·거울 구조 | 대량 등록에서 별도 대상 |
| 같은 구조, 다른 색/촬영 각도 | 색상만으로 동일 대상이나 유사 사례를 배제하지 않음 |
| 문틀만 시공 vs 문+문틀 시공 | 견적 범위가 다르면 금액 제외 |
| 사진이 잘리거나 대상이 가려짐 | 임의 확정 없이 추가 사진 요청 |
| 높은 설명 유사도, 다른 실제 구조 | 시각 비교에서 제외 |
| 비교 실패/잘린 응답/없는 후보 ID | 금액 계산 안 함 |

분류 정답률뿐 아니라 서로 다른 대상을 합친 오류, 동일 대상이 나뉜 오류, 검색 후보 누락, 부적합 사례가 견적에 들어간 비율, 확인 요청 비율, 요청별 토큰·시간을 같이 기록한다. 이번 사용자 신고 사례는 모두 통과해야 하며, 그 외 서로 다른 시공 유형으로 검증 범위를 넓혀야 한다.
