# 관리자 화면 로딩 개선 (2026-10-27)

## 확인한 지연 경로

- 관리자 진입: 회사 인증 이후 샘플 초기화 API, 회사 설정, 시공 DB, 상담 수 조회가 모두 끝나야 홈이 표시됐다.
- 현장 목록: 상태 자동 갱신 API(클라이언트 제한 10초)가 끝나야 목록 조회를 시작했다.
- 홈: 오늘 업무와 내일 자재의 병렬 요청 중 느린 쪽이 완료될 때까지 두 결과 모두 화면에 반영되지 않았다.
- 현장 상세: 접혀 있는 거래처 연결은 전체 거래처/현장 자료를 조회했고, 변경 내역은 30초 간격으로 현장 작업 자료를 조회했다.
- 생산 오류 로그(약 50분 범위)에는 URL 파서 사용 중단 경고만 확인됐고, 조사 시점 DB 활성 세션에 잠금 대기는 관찰되지 않았다. 과거 누적 쿼리 통계로 현재 전체 속도를 단정하지 않는다. Vercel 라우트별 지연 지표 API는 조회되지 않아 실제 사용자의 초 단위 개선치는 측정하지 못했다.

## 변경

- 회사 인증은 유지하고 홈은 즉시 표시. 샘플 초기화/설정/상담 수는 뒤에서 조회한다. 시공 DB는 해당 탭을 열 때 읽고 기존 검색어/페이지를 유지한다. 새 업체의 샘플 초기화도 유지한다.
- 현장 목록과 상태 점검을 동시에 시작하고 목록을 먼저 표시. 실제 상태 변경이 있으면 목록을 한 번 갱신한다. 동일 화면에서 진행 중인 같은 업체의 상태 점검은 공유하며, 이전 조회나 다른 업체의 늦은 응답은 무시한다. 실패한 후속 갱신으로 이미 표시한 목록을 지우지 않는다.
- 오늘 업무와 내일 자재를 각각 도착하는 대로 표시한다.
- 거래처 연결/변경 내역은 최초 펼침에 조회한다. 접어도 거래처 입력 내용은 유지하며, 숨긴 변경 내역의 주기 조회는 중지한다.
- 시공 DB/등록 화면 코드는 해당 화면에서 불러온다.

DB 스키마, 저장된 현장/자재/금액, 권한 검사, 알림톡 발송 조건은 변경하지 않았다. 점검 중 실제 알림톡을 발송하지 않았다.

## 검증

- 전체 테스트 982개 통과. 느린 샘플 초기화, 내일 자재 조회 지연, 상태 점검 실패, 목록 재조회 경쟁, 업체 전환/화면 종료, 접힌 패널과 입력 보존 시나리오 포함.
- 최종 소규모 보완(시공 DB 검색 조건 보존) 관련 8개 테스트 재검증.
- 로컬 production build: 공개 클라이언트 설정에 빌드용 비밀 아닌 대체값 사용. 운영 인증정보나 데이터 없이 빌드 확인.
- 관리자 HTML에 포함된 초기 스크립트 gzip 합계: 변경 전 344,156 bytes, 변경 후 약 306 KB, 약 11% 감소. 이는 빌드 산출물 크기 비교이며 실기기 대기 시간 측정은 아니다.
- 운영 배포 상태와 기본 응답은 배포 후 확인한다. 인증된 모바일 화면은 사용자 세션 없이 직접 검증하지 않았다.
