# 현장 알림톡

- 관리자: 현장 상세 → 기본정보 → 고객 알림톡 보내기. 저장된 고객 정보로 미리보기를 조회한 뒤 명시적으로 발송한다.
- 슈퍼관리자: `/super-admin/alimtalk`. 실제 입금/승인된 지급을 확인한 뒤 기존 횟수제 계정에 충전하고 사용을 켠다. 이 화면은 결제를 수행하지 않는다. 원화 단가를 임의로 정하지 않는다.
- 시공자: 날짜별 배정 저장 성공 후 새로 추가된 시공자에게 배정일 전체를 안내한다. 역할 변경/배정 해제는 기존 앱 알림을 유지한다. 동일 내용 재저장으로 재발송/차감하지 않는다.
- 환경변수: `SOLAPI_API_KEY`, `SOLAPI_API_SECRET`, `SOLAPI_KAKAO_PF_ID`, `SOLAPI_TEMPLATE_SITE_ASSIGNED`, `SOLAPI_TEMPLATE_CUSTOMER_SCHEDULE` (서버 전용). API 키/시크릿은 Secret 권장. 정산 cron은 기존 `CRON_SECRET` 사용.
- 솔라피 승인 템플릿의 본문이 앱의 미리보기와 일치할 때만 보낸다. 템플릿이 승인 전이면 발송·차감하지 않는다. 변수는 등록된 한국어 키(`#{고객명}` 등)를 그대로 전달한다. 문자 대체발송은 항상 끈다.
- DB 마이그레이션: `supabase/migrations/20261025015339_site_alimtalk_solapi.sql`. 기존 `alimtalk_accounts`, `alimtalk_credit_entries`, `alimtalk_deliveries`를 보존하고 현장 참조/서비스 전용 예약 함수를 추가한다. 모든 테이블은 RLS 및 클라이언트 접근 금지. 공개 실행 권한 없음.
- 예약 시 업체 계정을 잠그고 1회 차감한다. 중복 요청/다른 업체/잔액 부족/미확정 기존 발송은 거절한다. 최종 성공이면 확정 차감, 최종 실패면 1회만 복구한다.
- 발송 API가 `2000`으로 응답해도 "발송 요청됨"이며 수신 성공이 아니다. `/api/alimtalk/reconcile`이 매일 한국시간 오전 9시 30분에 최종 `COMPLETE/4000` 성공 또는 실패를 확인한다(Vercel Hobby의 일일 예약 제한). 현장/운영 화면 새로고침으로 즉시 갱신할 수도 있다.
- 타임아웃/불명확 응답은 `unknown` 또는 `reserved`로 유지하고 자동 재전송/환불하지 않는다. 메시지 ID를 잃은 경우 슈퍼관리자 화면에서 솔라피 메시지 ID를 입력해 `customFields.deliveryId`가 일치하는 결과만 연결한다.
- 대규모 배정의 실행시간 제한 때문에 한 저장 요청에서 시공자 알림톡은 최대 10명까지 처리한다. 나머지는 기존 앱 알림을 유지하고 관리자에게 알림톡 미발송 안내를 기록한다. 별도 대량 발송 큐는 포함하지 않는다.
- 실제 발송 검증은 템플릿 승인, 업체 사용 설정, 충전 후 지정한 테스트 번호로 수행해야 한다. 자동 테스트는 가짜 번호/모의 솔라피와 격리 DB를 사용한다.

검증: `node --test tests/site-alimtalk*.test.mjs`; `npm run build`.
공식 문서: https://solapi.com/developers/api/messages-ata , https://solapi.com/developers/api/messages , https://solapi.com/developers/api/msg-getList , https://solapi.com/developers/api/authentication-api-key

## 고객 전날 자동 안내
매일 한국시간 12~13시 사이 `/api/alimtalk/customer-reminders`가 첫 시공일이 다음 날인 현장을 조회한다. Hobby Cron은 해당 시간대 안에서 실행되므로 정확한 12시 정각은 보장되지 않는다. 기존 고객 일정 템플릿을 재사용하고, 업체 알림톡 활성화·잔여 횟수·템플릿 승인이 필요하다. 취소/완료 현장은 제외하고 고객 휴대폰, 현장 정보와 업체 연락처 누락 시 발송하지 않는다. 수동 일정 안내와 별도로 현장/첫 시공일마다 한 번만 예약하며, 실패·불명 상태도 자동 재시도하지 않는다. 실패 확정 시 횟수는 복구된다. 당일 등록/일정 변경이 실행 시각 이후라면 다음 날을 위한 추가 실행은 없다.

## 운영 업체 예외
필름장이의 고정 업체 ID `2ddfe3d9-4411-4991-ae35-5b876be411bc`만 앱 요금·AI/일반 기능 사용 한도·알림톡 충전을 면제한다. 이름 변경이나 클라이언트의 무제한 플래그로 권한을 얻을 수 없다. 알림톡 계정은 활성화하되 발송별 `credit_exempt`를 기록하여 차감/실패 복구로 충전 횟수가 변하지 않는다. 중복 방지·템플릿 승인·유효 연락처 검증은 유지한다. 운영 구독은 0원/다음 결제 없음으로 고정하고 결제 API 및 정기결제 대상에서 제외한다. 외부 솔라피/API 실제 사용료는 운영 계정에서 발생한다.

## 시공자 전날 알림톡
`database/worker_alimtalk_reminders.sql` 적용 후 매일 한국시간 12~13시 `/api/alimtalk/worker-reminders` 실행. 현재 배정된 각 작업일 전날 현장/시공자/작업일마다 한 번 발송한다. 기존 시공자 배정 템플릿을 그대로 재사용하여 추가 템플릿·환경변수는 필요 없다. 날짜별 배정이 한 건이라도 있으면 날짜별 배정만 따르고, 없는 현장에만 기존 현장 전체 배정을 사용한다. 예약 함수에서 작업일·배정·활성 업체/시공자·현장 상태를 다시 검증한다. 필름장이 운영 업체는 충전 차감 없이, 일반 업체는 1회 차감한다. 검수 전 템플릿·누락 정보·배정 해제/취소 현장은 발송하지 않는다. 점심 실행 후 추가/변경된 배정은 그날 자동 재실행하지 않는다.

## 시공자 일정 변경·배정 취소
`database/worker_assignment_change_alimtalk.sql` 적용. `sites`, 날짜별 배정 및 기존 현장 배정의 변경 전 상태를 트랜잭션별로 보관하고 커밋 시 최종 상태와 비교해 `worker_assignment_alerts`에 기록한다. 과거 날짜·역할만 변경·동일 배정 재저장·트랜잭션 롤백은 발송하지 않는다. 새 시공자는 기존 배정 안내를 받고, 기존 시공자의 날짜 추가/이동은 변경 전·후 일정 안내, 날짜 제거/현장 취소는 제거된 날짜만 취소 안내를 받는다. 취소 시 현장 접근 버튼은 사용하지 않는다.

환경변수 `SOLAPI_TEMPLATE_WORKER_SCHEDULE_CHANGED`, `SOLAPI_TEMPLATE_WORKER_CANCELED`의 승인 템플릿 본문과 일치해야 발송한다. 각 저장 API 및 일정 수정 후 소유자 인증 API에서 즉시 처리하며, 누락된 요청은 매일 정산 Cron에서 재확인한다. 미발송 안내는 24시간 후 만료하며, 이후 수정된 오래된 안내는 대체 처리한다. 이미 예약/접수된 발송은 결과 불명이어도 자동 재발송하지 않는다. 240초 처리 예산 이후 남은 미예약 안내는 다음 처리로 넘긴다. 실패 확정 시 일반 업체만 횟수를 복구하고 운영 업체는 차감/복구가 없다. 기존 앱 알림·푸시는 유지한다.

## 솔라피 실제 잔액
슈퍼관리자 홈과 알림톡 관리 화면에 솔라피 잔액 카드를 표시한다. `/api/super-admin/solapi-balance`는 활성 슈퍼관리자 인증 후 서버에서 `/cash/v1/balance`를 조회하고 숫자 잔액·포인트와 조회 시각만 반환한다. `balance`에는 이미 예치금의 부가세 제외 금액이 포함되므로 `deposit`을 다시 더하지 않는다. 화면의 발송 가능 총액은 `balance + point`이며 업체별 앱 충전 횟수와 구분한다. 조회 실패는 0원이 아닌 조회 오류로 표시한다. 충전은 공식 콘솔 `https://console.solapi.com/balance`를 새 창으로 열고 사용자가 직접 진행한다. 화면 복귀 시 5초 간격으로 조회하며 수동 새로고침도 제공한다.
