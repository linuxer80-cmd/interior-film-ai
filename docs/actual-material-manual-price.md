# 반출·반입 정산 자재의 직접 단가 저장

기존 일반 PATCH는 guard_settled_actual에서 차단되지만 오류가 일반 저장 실패로 숨겨졌다. 정산 자재의 단가 저장을 별도 service_role 전용 RPC로 연결한다.

RPC는 활성 업체 관리자·현장·actual 자재를 검증하고 잠근다. 저장된 사용량·제품·단위·메모와 제출값이 같아야 하며, 최신 updated_at도 확인한다. 현재 지원 단위는 m/미터다. 관리자 직접 단가를 비공개 테이블에 기록한 뒤 해당 자재의 금액을 계산한다. 자동 롤 계산은 명시적으로 단가를 저장한 해당 자재에만 직접 단가를 우선하고, 나머지 기존 자동 계산 경로는 유지한다.

자재 수정에서 제품이나 사용량도 바꾸려고 하면 원인을 표시한다. 예정 자재·반입 기록에서 원본을 수정해야 한다. 직접 단가는 실제 자재 행에 연결되며 해당 행이 삭제되면 함께 제거된다. 보고서 재제출이 자재를 삭제·재생성하는 경우에는 직접 단가를 다시 확인해야 한다.

앱 배포 후 운영 DB SQL Editor에서 database/actual_material_manual_price.sql을 실행한다. 앱 운영 DB는 현재 연결된 Supabase 프로젝트와 달라 직접 적용하지 않았다.

검증: 로컬 Postgres(PGlite)에서 19.4m×11,500원=223,100원 저장, 0원, 반복 적용, 권한·수량·제품·메모·버전 변경 차단, API fallback, 기존 자재 선택 시 비용 필드 유지 확인. 운영 계정 저장 성공은 SQL 적용 후 확인 필요.
